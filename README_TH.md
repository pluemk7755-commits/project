# Roo Nai Gor Dai — Snooker Club Management & Booking System

โปรเจกต์เว็บแอปสำหรับสาธิตการจัดการร้านสนุกเกอร์และระบบจองโต๊ะ พัฒนาด้วย Python, SQLite, HTML, CSS และ JavaScript โดยใช้ HTTP server ภายในโปรเจกต์

> **สถานะชุดไฟล์นี้:** เป็นชุดสำหรับทดสอบและส่งผู้สอนแบบส่วนตัว ไม่ใช่ระบบ Production ที่เปิดให้บริการบนอินเทอร์เน็ต

## 1. ความสามารถที่มีในโปรเจกต์

### ฝั่งสมาชิก
- สมัครสมาชิก เข้าสู่ระบบ และจัดการข้อมูลโปรไฟล์
- ดูโต๊ะสนุกเกอร์/พูลและสถานะโต๊ะ
- เลือกเวลาและจองโต๊ะ
- เลือกเช่าไม้คิวจากรายการที่ระบบกำหนด
- แนบสลิปเพื่อรอผู้ดูแลตรวจสอบ
- ตรวจสอบสถานะการจอง รายการของฉัน และใบเสร็จตามสิทธิ์
- ใช้คะแนนสะสมและ Booking Credit ตามเงื่อนไขของระบบ
- ขอเปลี่ยนรหัสผ่านด้วย OTP ผ่านอีเมลที่ลงทะเบียนไว้

### ฝั่งผู้ดูแลระบบ (ADMIN)
- ดูภาพรวมร้าน รายการจอง และสถานะการเข้าใช้บริการ
- ตรวจสอบและอนุมัติ/ปฏิเสธสลิปด้วยตนเอง
- จัดการโต๊ะ สมาชิก และบัญชีผู้ดูแล
- ดูข้อมูลรายได้จากรายการชำระเงินที่ได้รับการอนุมัติ
- เช็กอิน เช็กเอาต์ และจัดการสถานะรายการจอง

บัญชีผู้ดูแลที่ใช้งานอยู่มีสิทธิ์จัดการระบบเท่าเทียมกัน บัญชีเดิมและบัญชีผู้ทดลองถูกเก็บแยกกัน ไม่เขียนทับรหัสผ่านเดิมของบัญชีใด

## 3. บัญชีผู้ดูแลสำหรับทดสอบ

ดูรายละเอียดบัญชีได้จาก `ข้อมูลสำหรับผู้ทดสอบ/บัญชี_ADMIN_สำหรับทดสอบ.txt`

- `pluem` คือบัญชีผู้ดูแลเดิม โดยคงรหัสผ่านเดิมที่เจ้าของโปรเจกต์ตั้งไว้
- `RakA.Lin` คือบัญชีผู้ดูแลสำหรับทดลองระบบ ใช้รหัสผ่านทดสอบตามไฟล์ข้อมูลผู้ทดสอบ
- ทั้งสองบัญชีเปิดใช้งานและมีสิทธิ์ผู้ดูแลเท่ากัน

หากกรอกชื่อผู้ใช้หรือรหัสผ่าน ADMIN ไม่ถูกต้อง ระบบจะแสดงข้อความแจ้งเตือนและกลับมาที่หน้า `/staff/login` เพื่อให้ลองเข้าสู่ระบบอีกครั้ง

## 4. วิธีติดตั้งและเปิดใช้งานบนเครื่อง

1. ติดตั้ง Python 3.11 ขึ้นไป
2. เปิด Terminal/PowerShell ในโฟลเดอร์เดียวกับ `run.py`
3. ติดตั้งไลบรารีที่ต้องใช้:

   ```bash
   python -m pip install -r requirements.txt
   ```

4. เปิดระบบด้วยคำสั่ง:

   ```bash
   python run.py
   ```

   หรือเปิด `start_web.bat` บน Windows

5. เปิดหน้าเว็บที่ `http://127.0.0.1:8000`
6. หน้าเข้าสู่ระบบผู้ดูแลอยู่ที่ `http://127.0.0.1:8000/staff/login`

`start_web.bat` ตั้งค่าให้ฟังเฉพาะ `127.0.0.1` สำหรับใช้งานบนเครื่องตัวเอง ไม่ควรเปิดพอร์ตหรือส่งต่อ HTTP server นี้ออกอินเทอร์เน็ตโดยตรง

## 5. OTP และการลืมรหัสผ่าน

- OTP เป็นระบบสำหรับ **บัญชีสมาชิก** ไม่ใช่บัญชี ADMIN
- ระบบจะส่ง OTP ไปยังอีเมลที่มีบัญชีสมาชิกลงทะเบียนและเปิดใช้งานอยู่เท่านั้น
- ฐานข้อมูลของ ZIP นี้ยังไม่มีสมาชิก ดังนั้นหากต้องการทดสอบ OTP ต้องสมัครสมาชิกด้วยอีเมลที่จะใช้ทดสอบก่อน แล้วจึงไปที่หน้า `ลืมรหัสผ่าน`
- โค้ดเลือกใช้ Google Apps Script OTP relay และ Cloudflare Turnstile เมื่อมีการตั้งค่า URL/Site Key ที่ถูกต้อง โดยต้องใช้อินเทอร์เน็ตและต้องผ่าน Turnstile ก่อนส่งอีเมล
- `otp_service/otp_sender.gs` เป็นโค้ดสำหรับ Apps Script ส่วน `TURNSTILE_SECRET` ต้องเก็บไว้ใน Script Properties เท่านั้น ห้ามใส่ Secret Key ใน Repository
- ไฟล์นี้ไม่ได้บรรจุ `data/smtp.env` หรือรหัสผ่าน SMTP
- การทดสอบ Unit Tests ใช้การจำลองผู้ให้บริการส่งอีเมล จึงไม่ใช่หลักฐานยืนยันว่าอีเมลจริงส่งถึงกล่องจดหมายแล้ว

## 6. ระบบชำระเงินและข้อมูลที่ต้องระวัง

ชุดนี้เก็บ QR รับชำระเงินและข้อมูลบัญชีรับโอนเดิมไว้ใน `data/payee_qr.png` และ `data/payee_config.json` ผู้ดูแลต้องตรวจสลิปด้วยตนเอง ระบบไม่ได้เชื่อมต่อธนาคารเพื่อตรวจธุรกรรมอัตโนมัติ การแนบสลิปไม่ได้ยืนยันว่าได้รับเงินจริงแล้ว

**ควรเก็บ Repository นี้เป็น Private** เพราะไฟล์ QR และ `payee_config.json` มีข้อมูลบัญชีรับโอนจริง และไฟล์ข้อมูลผู้ทดสอบมีรหัสผ่านบัญชีทดลอง หากเปลี่ยน Repository เป็น Public บุคคลทั่วไปจะสามารถดาวน์โหลดข้อมูลเหล่านี้ได้

## 7. การทดสอบระบบ

รันชุดทดสอบจากโฟลเดอร์โปรเจกต์:

```bash
python -m unittest discover -s tests -p "test_*.py" -v
```

ตรวจไวยากรณ์ Python:

```bash
python -m compileall -q webapp run.py open_admin.py tools
```

ตรวจ JavaScript (หากติดตั้ง Node.js):

```bash
node --check static/app.js
```

ควรทดสอบบนสำเนาโปรเจกต์เสมอ เพราะการจอง การตรวจสลิป และการจัดการหลังร้านอาจเขียนข้อมูลลงฐานข้อมูล

## 8. ข้อจำกัดของชุดนี้

- เป็นระบบสาธิตที่เปิดด้วย Python HTTP server ในเครื่อง ไม่ใช่เว็บไซต์ที่ GitHub โฮสต์ให้โดยอัตโนมัติ
- ไม่มี Payment Gateway และไม่มีการตรวจสอบรายการโอนจากธนาคารอัตโนมัติ
- การส่ง OTP จริงขึ้นอยู่กับการตั้งค่าและสถานะการให้บริการของ Google Apps Script, Cloudflare Turnstile, โควตาอีเมล และการเชื่อมต่ออินเทอร์เน็ต
- ก่อนนำไปเปิดใช้งานจริงบนอินเทอร์เน็ต ต้องออกแบบ HTTPS, การตั้งค่าเซิร์ฟเวอร์, การจัดเก็บความลับ และการป้องกันการเข้าถึงใหม่ให้เหมาะสม
